## Task 1: Implement `create()` method on RecreationRidingService
- **Status**: `completed`
- **Priority**: high
- **Depends On**: None
- **Description**:
  - Add `use` imports for `DB`, `Service`, `RecreationalRiding`, `PriceOptionUnit`, `ServiceType`, `ActivationStatus`.
  - Implement `create(array $data): RecreationalRiding` public method.
  - Wrap entire body in `DB::transaction(function () use ($data) { ... })`.
  - **Step 1 — Service creation**: Build translatable `name` (ar required, en optional) and `description` (ar required, en optional) arrays from `$data`. Create `Service` with fillable: `name`, `description`, `center_id`, `status = ActivationStatus::ACTIVE`, `type = ServiceType::RecreationRiding`. Slug auto-generated by model booted hook.
  - **Step 2 — RecreationalRiding creation**: Instantiate `new RecreationalRiding()`, use `service()->associate($service)`, then `save()` (avoids mass-assignment when no fillable on pivot model).
  - **Step 3 — PriceOptions creation**: Iterate `$data['price_options']`. For each item, call `$service->priceOptions()->create(['quantity' => $item['duration'], 'price' => $item['price'], 'unit' => PriceOptionUnit::MINUTE, 'name' => null])`.
  - **Step 4 — Schedules creation**: Loop `$data['days']` as `$day`. For each consecutive pair `($i*2, $i*2+1)` in `$data['hours']`, call `$riding->schedules()->create(['day_of_week' => $day, 'start_time' => $hours[$i*2], 'end_time' => $hours[$i*2+1]])`.
  - **Return**: Eager-load with `$riding->load(['service.priceOptions', 'schedules'])` and return.
- **Acceptance Criteria Addressed**: AC-1, AC-2, AC-3, AC-4, AC-8, AC-10
- **Test Requirements**:
  - `rule` TR-1.1: After calling `create()`, `Service::count()` increases by exactly 1, `RecreationalRiding::count()` increases by exactly 1. Evidence: ✅ Pest CP-R1 test, 6 assertions, Service/RecreationalRiding counts +1 each.
  - `rule` TR-1.2: Created Service has `type === ServiceType::RecreationRiding`, `status === ActivationStatus::ACTIVE`, `center_id === data['center_id']`. Evidence: ✅ CP-R1 test assertions on type/enum/status/center_id.
  - `rule` TR-1.3: Service `name` JSON column contains `ar` key and optionally `en` key matching input. Same for `description`. Evidence: ✅ CP-R2 test — ar-only create produces getTranslations() without en key; ar+en create produces both keys with exact values.
  - `rule` TR-1.4: PriceOption count === `count($data['price_options'])`; each row has `unit === PriceOptionUnit::MINUTE`, `quantity === duration`, `price === input price`. Evidence: ✅ CP-R3 test — 2 rows sorted by quantity 30/60 with matching prices, MINUTE unit, name=null.
  - `rule` TR-1.5: Schedule count === `count($data['days']) * count($data['hours'])/2`; every (day, start, end) triple exists. Evidence: ✅ CP-R4 test — 3×2=6 rows, days {0,2,4}×slots {09-12,14-17}, polymorphic FKs correct.
  - `rule` TR-1.6: On a forced failure (e.g., throw after Service creation inside a test wrapper), all four table counts are unchanged. Evidence: ✅ CP-R8 create-rollback test — anonymous subclass throws after Service+Riding creation; 4 table counts all identical pre/post.
  - `rule` TR-1.7: Returned `$riding` has `service`, `service.priceOptions`, and `schedules` relations loaded (via `relationLoaded()`). Evidence: ✅ CP-R9 test, relationLoaded() triple all true post-create.
- **Notes**: Ensured `ActivationStatus` is imported from `Modules\Support\Enums\ActivationStatus`. Used `associate()` + `save()` pattern for RecreationalRiding to avoid fillable requirement since the pivot model has no `$fillable`.

## Task 2: Implement `update()` method on RecreationRidingService
- **Status**: `completed`
- **Priority**: high
- **Depends On**: Task 1
- **Description**:
  - Implement `update(RecreationalRiding $riding, array $data): RecreationalRiding` public method.
  - Wrap entire body in `DB::transaction(function () use ($riding, $data) { ... })`.
  - **Lock & Load**: Fetch service via `Service::query()->whereKey($riding->service_id)->lockForUpdate()->firstOrFail()`.
  - **Step 1 — Update Service translations**: Build new `name` and `description` arrays (ar required, en optional) from `$data`. Call `$service->update(['name' => $nameArr, 'description' => $descriptionArr])`. Do NOT change `type`, `center_id`, `status`, `slug`.
  - **Step 2 — Sync PriceOptions**: Call `$service->priceOptions()->delete()` then re-create all from `$data['price_options']` (same mapping as Task 1, Step 3).
  - **Step 3 — Sync Schedules**: Call `$riding->schedules()->delete()` then re-create all from `$data['days']` + `$data['hours']` (same mapping as Task 1, Step 4).
  - **Return**: `$riding = $riding->fresh();` then `$riding->load(['service.priceOptions', 'schedules'])` and return (fresh instance per NFR-4).
